# Security reporting

For a credential, private-data exposure, unsafe repository script or other sensitive finding, use [GitHub private vulnerability reporting](https://github.com/VINASIG/vinasig-brand-assets/security/advisories/new).

Include the affected commit, relative path, reproduction steps and impact. Omit plaintext credentials, personal data and unrelated asset uploads. Do not open a public issue containing sensitive evidence.

This archive runs checks against local files and authorized test fixtures. Reports remain in ignored `output/` or CI artifacts. The integrity gates detect byte or metadata changes against the reviewed archive; they are not a malware scan or an authoring-application certification for proprietary source formats.

Use [repository issues](https://github.com/VINASIG/vinasig-brand-assets/issues) for non-sensitive catalog and documentation defects. Reporting or fixing a security issue does not change [asset rights](ASSET_RIGHTS.md).
